# Standalone recorded DLSS-G replay

- Created: 2026-09-10
- Updated: 2026-09-10
- Status: standalone implementation verified against recorded inputs; scene generalization and quality experiments continue
- Deployment: standalone only; no game attachment
- Deprecated: no
- Scope: GFR1 evaluation packets, RGBA8 color/HUDless, RGBA16F motion, R32 depth, 2x/4x generated phases

This executable creates a D3D12 device and a fresh native FG feature, uploads recorded inputs, calls the locally supplied NVIDIA provider and saves each generated phase. It has no window, input automation or game-scene simulation. Optional prepared MV/depth files are substituted before evaluation. Candidate preparation remains separate, allowing the production correction code or offline experiments to generate those files.

Paths, dimensions, frame count and multiplier come from a UTF-8 JSON manifest. Dimensions are configurable; the resource format profile is currently fixed and must be declared as `rgba8-mv16f-depth32`. Input files use `frame-NN-index-S.bin`, with S=0 color, 7 HUDless, 4 motion and 5 depth. The GFR1 packet carries recorded evaluation parameters and inline matrix/vector payloads. Unmapped non-null pointers are rejected. Frame zero resets the fresh feature. Creation defaults are explicitly reconstructed, not captured; unknown internal history is not reproduced.

Required fields are `provider`, `capture`, `arguments`, `output`, `outputWidth`, `outputHeight`, `renderWidth`, `renderHeight`, `frames`, `generatedCount`, `applicationId`, `sdkVersion` and `formatProfile`. Relative paths resolve against the manifest. `generatedCount` is 1 or 3. Three requires the caller's `unlock` DLL. `overrides` optionally names prepared replacement motion/depth files. Output must not already exist. No DLL is installed into a game directory.

Build using `build.ps1` from an x64 Visual Studio Developer PowerShell. Run the resulting `nvngx.dll.glass-replay.exe manifest.json`. The filename preserves the provider caller-name convention already observed in the local replay experiment. Provider and unlock identity must be recorded for comparisons. Neither is bundled.

Prefer `python run.py manifest.json --executable path/to/nvngx.dll.glass-replay.exe`. This requires `providerSha256` and, for 4x, `unlockSha256`. It verifies binary identities, packet frame count and every selected input length, inventories original/replacement hashes, validates every generated phase, and writes a report beside the output. Use `--compare reference-output --expect-identical` for a repeatability check. Ordinary candidate comparisons omit `--expect-identical`; differences are recorded without treating either candidate as visually better. Python 3.11 or later is required; no third-party Python packages are used.

The initial 24-frame 4x recording produced 72 successful outputs twice. All outputs matched each other and the preceding local replay byte-for-byte. A third run through the Python validator also matched all 72. An eight-frame prefix ran successfully at 2x, producing eight outputs. These checks establish the port's recorded-input behavior, not new ghosting improvement or coverage of every dimension/format/provider version. The current game files were unchanged.

Compare candidates with identical original packets, creation defaults, binaries, resets and frame order. Repeat the baseline to check reproducibility. Inspect real generated frames and changed-input masks; lower photometric error does not prove better FG. CPU/GPU drains in this offline harness are synchronization for correctness, not a model for the final game's performance.

## Separated-layer experiment

Test both independent background motion behind a stationary transparent surface and camera-relative motion of both layers. The target includes windows and other transparent foregrounds; a cup fixture alone does not establish general acceptance. Preserve transmitted motion rather than forcing the whole mixed pixel onto foreground depth/motion.

`build_layer_composite.ps1` builds the independent `LayerComposite.exe` runner for `../../GlassLayerComposite.hlsl`. It reads eight RGBA32F files named `input-0.bin` through `input-7.bin`: previous/current accumulated source color, previous/current RGB transmission, FG-generated background, fallback generated color, previous/current normalized endpoint offsets packed into XY/ZW, and admission data (X: correspondence valid, Y: correction footprint). Both admission components must equal 1. It writes RGBA32F. Invoke with `shader input-directory width height phase output-file [admitted]`; existing output files are rejected. This runner has no FG call, capture hook or game attachment. It consumes a previously generated background.

### Independent resolutions and valid regions

The optional `input-layout.txt` contains exactly eight rows in input order. Each row is `textureWidth textureHeight originX originY extentWidth extentHeight`, in that input's own texels. Without this file, all inputs default to the output size and full extent. Every allocation and extent must be positive and in bounds; the test runner limits dimensions to 8192. Its per-resource upload footprint follows the actual allocation. The fallback region must exactly match the selected output size so pixels outside correction can be copied without resampling. Padded fallback allocations are supported. Changing the output stage therefore requires the original fallback for that stage, not an arbitrary resize hidden inside the shader.

For output pixel p, `u = (p + 0.5) / outputSize`. Each endpoint is `u + offset`, and each source maps that normalized coordinate into its own valid region. Filtering clamps to that region's texel centers, excluding stale allocation padding. F/T and generated background use linear filtering; admission flags use a point load. Previous and current sizes may differ. No fixed render-to-final ratio or dimensions identify the resource or material. The output is an owned texture of the selected size.

Input 6 stores **offsets, not absolute endpoint UVs**. Zero offsets preserve the original output coordinate even on a 1x1 correspondence grid. Absolute UVs on a coarse grid can lock boundary pixels to coarse texel centers. This changes the isolated ABI: rebuild the runner (36 root constants) and regenerate old absolute-UV input files. For a verified constant current-to-previous normalized surface displacement m and interpolation phase a, previous/current offsets are `a*m` and `-(1-a)*m`. Raw engine motion must first use its documented units, direction, valid extent and jitter convention. Arbitrary motion and occlusion need verified endpoint correspondences; this translation example is not a runtime estimator.

All valid regions must represent the same view. Correspondence admission must cover the contributing filter samples and reject discontinuities or unknown correspondence; sampling an offset texture alone does not prove its validity. Color domain, exposure, frame pair, projection/jitter, occlusion, resource identity and GPU lifetime remain host requirements. Resizing a texture establishes none of them. The shader can compose at a chosen intermediate or final size, but it does not intercept an arbitrary internal DLSS stage or infer a color conversion. Lost detail at a lower sampling resolution is not reconstructed by this coordinate mapping.

Run `python test_layer_spaces.py --executable <exe> --shader <hlsl> --output <fresh-directory>` to check the mapping with independent analytic affine fields. Five configurations cover up/downsampling, reversed previous/current size changes, odd dimensions, poisoned padding, nonzero origins, a 1x1 zero-motion grid and categorical admission. All 326,970 GPU pixels passed at three phases; maximum reference error was 0.00002981 in the fixture's linear RGB units. All 115,770 rejected pixels retained fallback bits, and ten malformed-layout attempts were rejected before GPU work. This is coordinate and buffer validation, not visual acceptance of a game correction.

A separate controlled fixture used actual 4x FG with 640x360 MV/depth and 1280x720 final color: two runs produced 72 outputs. At frame 8, phase 0.5, the GPU compositor used 800x450 previous F/T, 960x540 current F/T, a 32x18 offset grid, distinct padded allocations and 1280x720 generated background. Composition at 1280x720 matched the CPU displayed reference exactly; composition at 960x540 differed by at most one 8-bit level. Fallback was exact outside correction in both. Direct image inspection showed reduced displaced outlines but softer thin detail in the reduced-resolution layers. This uses frozen captured material values, a synthetic moving figure and a known linear color transform; there was no SR/RR call or actual game-stage insertion.

The official [DLSS-G dynamic-resolution contract](https://github.com/NVIDIA-RTX/Streamline/blob/main/docs/ProgrammingGuideDLSS_G.md#100-dlss-g-and-dynamic-resolution) permits changing MV/depth extents with dynamic mode configured, while final color size stays fixed per feature. A final-output resize follows the host's feature/resize lifecycle. Flexible layer sampling does not override those provider constraints. The current replay harness tests fixed resource sizes per run; the different endpoint sizes above are compositor inputs, not a claimed per-frame dynamic-resolution FG test.

Run `python test_layer_composite.py --executable <exe> --shader <hlsl> --output <fresh-directory>` for the standard-library-only synthetic contract check. The 2,048-pixel GPU check covers three generated phases, global rejection, invalid/unknown correspondence, nonfinite inputs, unsupported transmission, HDR/additive/opaque colors and alpha preservation. Separately, the shader's 1280x720 output on a recorded synthetic background-FG image matched the Python endpoint-warp reference at every valid interior 8-bit pixel.

A controlled no-refraction scene compared background motion, all-surface motion, binary gradient-energy selection and blended motion through 12 rendered frames of actual 4x FG. Across frames 4–11 and all three phases, cup-region RGB MAE against analytic intermediate-time truth was 5.42, 6.13, 4.37 and 4.99 respectively (8-bit levels). A fifth background-only FG run with separately warped endpoint source/transmission reduced cup MAE to 1.48 and visibly removed the prominent duplicated cup outlines in the inspected middle-phase frame. Pane MAE was 1.00 versus 0.95 for the original, so the experiment is not a universal improvement. Each run produced 36 successful generated outputs. The opaque control put phases near their intended positions but retained roughly 1.3-pixel edge/centroid errors; this is an approximate quality control, not exact temporal calibration.

These results assume known layer separation, known constant surface/background translation, a shared linear blend domain, no refraction and no independently moving overlapping transparent layers. Actual game F/T sequences, background, endpoint correspondences, tone mapping/exposure and resource ownership have not passed those requirements. Do not enable the compositor on the current game inputs. Full-frame and actual generated images were inspected; synthetic success does not approve game deployment. The new shader is isolated source and is not copied into the production package or called by `NativeHost`.

The correction footprint is distinct from endpoint validity and actual surface coverage. Outside it, retain the original generated color. Inside it, neutral F=0/T=1 restores background to erase displaced foreground ghosts. Derive its extent from verified relative motion; the current fixture uses known motion and is not a runtime estimator. The GPU contract checks both neutral and non-neutral rejection outside the footprint, restoration inside it, and faint nonzero layers. In a stationary captured-material fixture over a moving synthetic figure, the displayed output matches the CPU reference, with 887,331 pixels outside the footprint preserved exactly. No real-time capture or game-color conversion is supplied by this runner.

The current official [DLSS-G resource requirements](https://github.com/NVIDIA-RTX/Streamline/blob/main/docs/ProgrammingGuideDLSS_G.md#51-required-and-optional-resources) require HUDless to have the final backbuffer's color space and post-processing. Material F/T from an earlier HDR pass cannot be mixed with those final pixels without a verified common-domain conversion. A known synthetic Reinhard/gamma transform is not evidence for the game's transform.
